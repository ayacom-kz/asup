# АСУП Эмбамунайгаз · кликабельный прототип (T-056, T-058)

Прототип для презентации дизайна. Работает в браузере на тестовых данных, без сервера.
Админка, планшет оператора и настенный дисплей используют **общие данные**: выдача на планшете появляется в журнале админки.

## Запуск

Нужен Node.js 22+.

```
cd prototype
npm ci          # один раз
npm run dev     # http://localhost:5173
```

Если на диске C мало места, установите зависимости с кэшем на другом диске: `npm ci --cache ./.npm-cache-tmp`, затем удалите папку `.npm-cache-tmp`.

Статическая сборка: `npm run build` → папка `dist/`. Её можно открыть через любой веб-сервер (например, `npx vite preview`).
Тесты логики и сценариев приёмки: `npm test`.

## Логины (пароль у всех `demo`)

- Админка: `admin` — администратор, `engineer` — инженер, `buh` — бухгалтерия, `blocked` — отключённая учётка.
- Планшет: `operator` — оператор, `operator2` — оператор без права ручной выдачи.

Права ролей — предложение из макета «Роли», не утверждены.

## Сценарий презентации (≈10 минут)

1. Откройте `#/` → «Стенд для презентации». Во второй вкладке — `#/admin/journal` (вход admin / demo).
2. **Выдача.** В пульте нажмите на Армана → на планшете «Выдано: обед», на настенном дисплее зелёное «Можно». Через 2 секунды запись появляется в журнале админки с подсветкой.
3. **Повторная попытка.** Нажмите на Виктора → «Лимит питания уже использован», на дисплее жёлтое «Нельзя» с причиной. В локальном журнале фильтр «Отказы».
4. **Вне окна.** Время 23:30 → Т1 показывает «Вне основного приёма», отказ направляет на Т2.
5. **Т2.** Выберите «Вода» на планшете, в пульте переключите терминал на Т2 и нажмите на сотрудника. После выдачи выбор сбрасывается.
6. **Связь.** «Только SIM» → жёлтый статус резервного канала. «Нет связи» → проведите 1–2 выдачи: «Ожидают отправки». Нажмите «LAN» → «Отправляется» → «Центр подтвердил приём». «Повторить доставку» → в логе пульта «дублей отклонено», в журнале по одной записи на UUID.
7. **Событие терминала.** В пульте «Только событие терминала» → в журнале запись «Событие терминала · Тестовое · Лицо распознано», выдача не создаётся.
8. **Ручная операция.** Кнопка на планшете → 3 шага. Для Виктора и обеда — отказ по лимиту. Под `operator2` — «нет права».
9. **Админка.** Откройте запись корректировки → «Открыть исходную запись». Создайте корректировку к любой выдаче. В «Демо» (кнопка внизу справа) включите сбои: ошибка загрузки, сохранения, сессия, устаревшие данные, офлайн-конфликт.
10. **Настройки.** Столовая №1 → поменяйте окно обеда → «Сохранить для столовой №1» — окно сразу меняется на планшете. Пересечение окон не сохраняется.

«Держать результат» в пульте не даёт экрану вернуться в ожидание через 8 секунд — удобно, когда показываете и рассказываете.
Данные хранятся в браузере. Сброс — «Начать заново» в пульте (два нажатия) или «Сбросить демо-данные» в каталоге.

## Как устроено

- `src/data.js` — сотрудники, 32 точки, окна питания, роли (тестовые данные).
- `src/logic.js` — проверка права на питание, приём пакета в центре без дублей по `eventId`, конфликты, наследование настроек.
- `src/store.js` — общее состояние: точка (локальный журнал, очередь, связь), центр (журнал, справочник, настройки), админка. Синхронизация вкладок — `localStorage` + `BroadcastChannel`.
- `src/tablet`, `src/display`, `src/admin`, `src/stand`, `src/catalog` — экраны.
- Модель события: `eventId, pointId, terminal, employeeId, occurredAt, kind (terminal | meal | correction), result, meal, reason, syncStatus, sourceEventId`. Это модель прототипа; контракт API согласуют Александр и Тимур.

## Ограничения

- Работает в пределах одного браузера: две вкладки на одном компьютере синхронизируются, два разных устройства — нет. Для показа на настоящем планшете и ноутбуке нужен сервер центра (следующая итерация).
- Распознавание и оборудование имитируются. Персональные данные вымышленные.
- Настенный дисплей — новый экран, макета не было. Открытый вопрос: показывать ли фото и полное имя на общем экране. Сейчас показывается имя и инициал фамилии, без фото.
